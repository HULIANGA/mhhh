# M4 分步实施计划

## 目标与边界

M4 在已经稳定的 M3 狩猎闭环上完成第一轮战斗核心美术与声音替换：将程序化占位猎人、大剑和怪物替换为 Blender 制作的简约卡通低模资产，接入基础骨骼动画和原创合成音效，并把怪物生命信息整理为适合单怪物战斗的顶部 UI。

M4 不改变 M3 已确认的玩法契约：

- Godot 的战斗状态机、`CharacterBody3D`、Resource 数值和物理帧仍是移动、伤害窗口与胜负结果的唯一权威。
- 骨骼动画只负责表现，不使用根运动，不通过动画事件决定伤害、位移或结算。
- 玩家剑刃与怪物双角的判定继续跟随可见模型，但改为读取稳定挂点，不再依赖具体网格节点或占位模型尺寸。
- 扑击和冲撞的世界位移、连续路径探针、障碍互动及竞技场边界保持不变。
- 保留扑击落点圈与冲撞路径；正常游戏移除怪物头顶生命、招式名和阶段文字，调试信息移入 F1。
- M4 只替换猎人、大剑和双角荒原兽。地面、训练靶、墙体、石柱、木障碍和外围装饰继续使用现有表现，并入 M5 场景打磨。
- 不新增招式、连段、装备、敌人种类、面部动画、布料模拟、导航或多怪物 UI。

## 已确认的视觉与声音方向

- **整体风格**：简约卡通低模，强调固定俯视角下的轮廓和动作可读性，不走写实路线。
- **材质**：少量纯色材质槽、顶点色和平面着色；M4 不制作 UV 手绘贴图。
- **猎人**：原创女性铠甲大剑角色，以《Claymore》中 Teresa 的银发女剑士气质为参考，使用银灰短发、浅色分片铠甲、深色内衬和项目现有青绿色点缀；不复刻原作纹章、服装分片或具体剑身设计。
- **怪物**：双角荒原兽，结合牛科宽肩、野猪低重心、粗前肢与短后躯，让横扫、扑击和冲撞都有自然且不同的动作轮廓。
- **音效**：全部由仓库内确定性脚本生成原创 WAV，不引入外部素材和许可依赖。

## 资产与技术契约

### Blender 与 GLB

- 锁定 Blender 5.2 LTS；Blender 安装包不进入仓库，通过文档说明安装并允许 `BLENDER_BIN` 指向本地可执行文件。
- `.blend` 源文件放入 `art/blender/`，Godot 使用的 `.glb` 放入 `assets/models/`；源文件与导出结果都提交。
- 统一使用 1 Blender 单位 = 1 米、Y 轴向上、角色正面为 `-Z`；导出前应用模型缩放与旋转。
- 所有动作使用原地动画，骨架根节点保持在物理原点；动画不得产生未被 Godot 状态机控制的世界位移。
- 提供 Blender 无界面导出和资产校验命令，检查 GLB 可导入、骨架和动作命名、挂点、材质及模型尺寸。
- 初期不引入 Git LFS；通过低模和无贴图约束控制 `.blend` 与 `.glb` 体积。

### 规模预算

| 资产 | 三角面上限 | 材质槽上限 |
|---|---:|---:|
| 女性猎人 | 15,000 | 6 |
| 双角荒原兽 | 20,000 | 5 |

### 稳定挂点

- 大剑必须提供 `WeaponSocket`、`BladeBase`、`BladeTip`。
- 怪物必须提供 `HornLBase`、`HornLTip`、`HornRBase`、`HornRTip`。
- 挂点名称、朝向和语义属于 M4 之后的资产公共接口；后续升级动画或模型时不得随意修改。
- 玩家攻击使用 `BladeBase → BladeTip` 的世界空间线段生成多点探针；横扫分别使用两组角根到角尖线段生成探针。
- 玩家和怪物胶囊碰撞体、扑击／冲撞身体路径探针不绑定骨骼，继续由玩法场景维护。

### 动画驱动

- 猎人表现层接收移动速度、动作状态、动作阶段、归一化阶段进度、蓄力档位、受击与倒地状态。
- 怪物表现层接收移动速度、攻击 ID、攻击阶段、归一化阶段进度、撞墙硬直、受击与死亡状态。
- 循环移动动画按实际速度调整播放速度；攻击动画按逻辑进度采样，避免渲染帧率造成动画与判定漂移。
- Blender/GLB 中的循环动作使用 `*_loop` 名称；Godot 导入器会移除该后缀，因此运行时适配层使用 `idle`、`run` 等名称并校验其循环模式。
- 表现层只能读取和展示玩法状态，不得反向触发生命变化、伤害、位移或胜负。
- 受击闪红使用实例级材质覆盖或统一表现参数，不直接改写导入模型的基础材质。

## 开发规则

每个步骤都是独立交付单元。一次开发只完成一个步骤，并满足以下条件后停止：

1. 当前步骤新增测试及 M1～M3 既有回归通过。
2. 当前步骤涉及的接口、资产命名和验收结果写入文档。
3. Godot 资源可重新导入，Web release 可成功导出。
4. 需要观察轮廓、动画、判定或声音的步骤由用户在浏览器中验收。
5. 验收后创建独立 Git 提交，再开始下一步骤。
6. 不提前实现下一步骤；若某一步变大，拆成 `.a`、`.b`，不改变后续编号。

## 实施步骤

### M4.1 Blender/GLB 工具链与空资产契约

状态（2026-09-16）：实现、资产导出校验、全量自动回归和双平台构建已完成。

范围：

- 建立 `art/blender/`、`assets/models/` 目录及无界面导出／校验脚本。
- 固定 Blender 版本、单位、坐标、正面方向、变换应用、材质和原地动画约定。
- 创建最小测试资产，验证骨架、动画、Marker3D 挂点和材质能通过 GLB 进入 Godot。
- 将资产导入检查接入开发命令；缺少 Blender 时允许运行游戏和既有测试，但显式跳过重新导出并报告原因。
- 记录 Mac 制作、Web/Windows 运行时的资产兼容要求。

完成标准：测试 GLB 可被 Godot 无错误导入，Web/Windows release 能包含并实例化模型；重复导出不产生意外结构变化。

### M4.2 表现适配层与判定解耦

状态（2026-09-16）：已完成。占位表现已接入独立适配节点，命中判定改为读取稳定挂点，既有玩法回归保持通过。

范围：

- 为猎人和怪物建立独立表现子场景及适配脚本，玩法控制器不再直接创建或操作程序化身体、腿、角和剑网格。
- 先用兼容占位表现接入新适配层，确保替换模型前所有玩法行为不变。
- 玩家剑刃和怪物双角命中改为读取稳定挂点；移除对 `MeshInstance3D`、固定剑长和角局部坐标的判定依赖。
- 将走路、攻击、扑击、冲撞、受击、倒地等表现入口集中到适配层。
- 改写直接断言占位腿、角、材质颜色和整体旋转的测试，改为验证表现状态、挂点轨迹和玩法结果。

完成标准：任意满足挂点契约的测试模型都能替换占位外观；剑击、横扫、扑击、冲撞、受击和重开回归全部通过。

### M4.3 大剑模型与判定对齐

范围：

- 独立制作简约卡通大剑，握把原点置于双手握持中心，保持厚重、直刃和固定俯视角下清晰的刀刃方向。
- 造型使用深色握把、低饱和金属护手、浅色宽刃和可见切刃，不复刻参考作品的具体剑身或纹章。
- 将 `BladeBase`、`BladeTip` 放在实际可见刃身上，保留当前大约 1.82 米的有效刀刃覆盖尺度。
- 接入猎人武器挂点，并验证静止、普攻、蓄力、取消和翻滚时模型不会脱手或穿过身体到不可接受程度。
- 增加挂点完整性与剑身判定对齐测试。

完成标准：浏览器中可见刀身与命中路径一致；不存在明显命中却无伤或隔空命中，M2/M3 攻击时序和伤害保持不变。

### M4.4 女性猎人低模、骨架与基础动作

范围：

- 制作原创女性铠甲猎人低模：银灰短发、浅色分片铠甲、深色内衬、青绿色不对称短披肩和重靴；弱化面部细节，不制作面部骨骼。
- 建立稳定人形骨架，至少包含根、骨盆、脊柱、头部、双臂、双腿和右手武器挂点。
- 制作并导出以下归一化动作：

| 动画名 | 用途 |
|---|---|
| `idle_loop` | 自由状态待机 |
| `run_loop` | 八方向移动的原地跑动 |
| `light_attack` | 单段普攻完整前摇、有效帧与收招 |
| `charge_enter` | 进入蓄力姿态 |
| `charge_hold` | 蓄力保持与张力循环 |
| `charge_release_1` | 一档蓄力释放 |
| `charge_release_2` | 二档蓄力释放 |
| `charge_cancel` | 提前松开或翻滚取消前的回正 |
| `dodge` | 无根运动翻滚 |
| `hit` | 短促受击反馈 |
| `defeated` | 倒地姿态 |

- 动画按现有 Resource 时长缩放或采样；不得调整体力、无敌帧、伤害窗口、移动速度和输入缓存。
- 蓄力保持可循环或定格；一档、二档切换必须保持当前蓄力阈值和满蓄自动释放行为。

完成标准：固定俯视角下可立即识别猎人朝向、大剑位置、蓄力、攻击、翻滚、受击和倒地；连续重开后动画恢复待机且无残留。

### M4.5 双角荒原兽低模、骨架与基础动作

范围：

- 制作宽肩、低头、粗前肢、短后躯和外展双角的荒原兽低模，使用低饱和土色、深色背部和浅色角部材质。
- 建立四足骨架和稳定双角挂点，确保挂点始终跟随可见角运动。
- 制作并导出以下归一化动作：

| 动画名 | 用途 |
|---|---|
| `idle_loop` | 待机与攻击冷却 |
| `run_loop` | 追击的原地四足跑动 |
| `sweep` | 横扫前摇、扫击与收招 |
| `pounce` | 俯身、腾起与落地收招 |
| `charge_windup` | 后撤、刨地、压低双角 |
| `charge_run` | 冲撞中的原地奔跑姿态 |
| `charge_recovery` | 正常冲撞停止后的收招 |
| `crash_stunned` | 撞击不可摧毁物后的侧倒与起身 |
| `hit` | 受击反馈 |
| `defeated` | 死亡倒地 |

- 扑击和冲撞只用骨骼动画表现姿态，世界位移继续由怪物状态机驱动。
- 前摇通过姿态、角部高亮、地面预警和声音表达；取消正常模式的全身阶段变色与头顶文字依赖。

完成标准：关闭阶段文字后仍能从动作轮廓区分三种招式；双角扫掠、扑击、冲撞、撞墙硬直和死亡判定保持 M3 结果。

### M4.6 顶部怪物 UI 与战斗可读性

范围：

- 在屏幕顶部中央加入单怪物生命组件，显示怪物名称、生命条和当前／最大生命数值。
- 战斗开始后显示怪物生命；受伤即时更新；胜负结算冻结最终数值；重开恢复满生命。
- 移除怪物头顶 `Label3D` 及正常模式下的招式名、`WINDUP`、`ACTIVE`、`RECOVERY`、`STUNNED` 文本。
- F1 调试区增加怪物状态、攻击 ID、攻击阶段和当前动画名。
- 保留扑击落点圈与冲撞路径，调整颜色和透明度以匹配新模型，但不得缩小或偏移其实际提示范围。
- 检查 1280×720 及窗口缩放后的布局，避免怪物生命条遮挡暂停按钮、命中反馈或战斗中心。

完成标准：正常模式只通过顶部 UI 显示怪物生命，场景中无怪物头顶调试文字；三招仍可清晰预判。

### M4.7 原创合成音效

范围：

- 新增固定随机种子和固定参数的音效生成脚本，输出确定性的单声道 WAV；重复执行应产生相同文件。
- 建立 `SFX` 音频总线和有限数量的可复用播放器，避免快速命中或连续重开持续创建节点。
- 玩家音效覆盖：轻攻击挥剑、蓄力达到一档、达到二档、蓄力释放、翻滚、受击、倒地。
- 怪物音效覆盖：横扫预兆／挥击、扑击预兆／起跳、冲撞蓄势／冲出、撞墙、受击、死亡。
- 交互音效覆盖：剑击命中、木障碍破碎、胜利、失败。
- 新增语义化音频事件 ID；声音由逻辑状态切换和伤害结果触发，不依赖显示文本或动画关键帧。
- 为高频声音设置最短重触发间隔；暂停和结算停止循环声，重开清理所有残留播放。
- M4 只建立 SFX 总线和默认平衡，不制作音量设置界面；设置界面仍属于 M5。

完成标准：不看招式文字也能通过姿态与声音区分三种攻击；翻滚成功不播放受击声；暂停、结算和连续重开无残留或叠加声音。

### M4.8 全量回归、构建与人工验收

范围：

- 新增资产契约测试，检查三个 GLB、骨架、动作、挂点和材质完整性。
- 新增动画与判定测试，验证大剑和双角在有效帧内移动、挂点轨迹贴合模型，动画不改变物理根节点。
- 新增 UI 与音频状态测试，覆盖受伤、死亡、暂停、失焦、结算和重开。
- 运行 M1～M3 全量回归及连续 10 局重开稳定性测试，确认节点、状态、输入、动画、音频和 UI 无残留。
- 执行 Godot 资源重新导入、Web 与 Windows x86_64 release 导出。
- 更新 README、开发计划和 `M4_ACCEPTANCE.md`。
- 浏览器连续完成至少 5 场，覆盖三种怪物招式、两档蓄力、翻滚规避、冲撞撞墙、胜负和连续重开。
- 人工逐帧抽查普攻、横扫、扑击与冲撞，确认不存在明显可见命中却无伤或隔空命中。

完成标准：所有自动测试和双平台构建通过；猎人、大剑和怪物轮廓清楚，模型与判定一致，正常模式无原型阶段文字，连续 5 场无动画、判定、音频或 UI 残留。

## 后续升级兼容性

M4 选择“骨骼动画 + Godot 逻辑混合驱动”，为后续更完整的骨骼全动画保留升级路径。只要骨架、挂点、动作 ID 和无根运动约定不变，后续可以逐个替换或增加动作剪辑，不需要重写战斗状态机。只有修改骨架比例、挂点语义或让动画接管世界位移时，才需要重新校准判定和玩法逻辑。

## 推荐执行方式

后续每轮直接使用“开始 M4.1”“开始 M4.2”等指令。完成当前编号后先自动回归、浏览器验收和提交，再进入下一编号；M4.8 通过后才把当前阶段切换为 M5。
