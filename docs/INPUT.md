# 统一游戏输入

当前只接入键鼠。接口为未来手柄和触屏保留扩展位置，没有添加虚拟摇杆、手柄绑定或移动端导出。

## 数据流

`Player/InputSource → HunterInputFrame → Hunter → 移动、朝向及后续战斗`

角色每个物理帧只调用一次输入源的 `sample(viewport, actor_position)`，并保存到 `input_frame`。后续战斗读取同一帧，不再自行读取键盘、鼠标、触点或摇杆。

| 输入字段 | 约定 |
|---|---|
| `movement: Vector2` | 屏幕平面方向：X 向右、Y 向下；长度 0～1，保留模拟输入强度。角色只限制最大长度，不把小幅输入强制归一化 |
| `aim_direction: Vector3` | 世界空间水平朝向；零向量表示保持原朝向。键鼠适配器将鼠标投射到地面并转换成方向 |
| `attack / charge / dodge` | 各自有 `pressed`、`held`、`released`，分别表示本物理帧按下、持续按住、本物理帧松开 |

普通攻击、蓄力、翻滚分别绑定左键、右键和空格。它们只在输入适配器中转换成意图；动作互斥、体力判断、普攻输入缓存、长按重复和命中结算由角色战斗状态机处理。

## 接入新设备

1. 继承 `HunterInputSource`，实现 `sample()` 和 `clear()`；返回独立的帧数据，不在采样时移动角色。
2. 替换玩家场景的 `InputSource` 节点脚本；也可注入符合该类型的节点，测试使用这种方式验证模拟量。
3. 由适配器处理摇杆死区、轴方向、触点追踪和设备断开。未来若同时接入多设备，由输入源统一选择设备，角色不负责仲裁。
4. 手柄左摇杆可提供 `movement`，右摇杆转换到世界平面后提供 `aim_direction`；松开右摇杆后输出零向量即可保持朝向。

暂停、继续与重置都会清理输入源及角色缓存。设备替换前应清理旧源，替换后调用 `hunter.clear_input()`。清理代表取消操作，不应制造“松开蓄力后出刀”的指令；键鼠源丢弃清理后首次采样的按钮状态，避免菜单点击进入战斗。

菜单操作 `pause/reset/debug` 与游戏动作分离，仍通过 InputMap 动作处理，因此暂停时可以恢复；未来可给这些动作增补手柄绑定。

## 验证

`python3 tools/dev.py test` 运行输入接口、移动、M2 战斗和 M3 玩家生命四组回归，验证按住／松开、取消无残留、半幅移动、方向瞄准、零方向保持、超范围限速、暂停／重置、动作状态约束、受击去重及翻滚免伤。

M2 的浏览器交互与手感已于 2026-09-16 通过人工验收；自动流程不会代替真实浏览器输入测试。尚未接入或验收真实手柄与触屏设备。
