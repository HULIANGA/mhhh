# 开发计划

## 已确认的方向

- 3D 固定俯视角、单人狩猎；观察破绽、谨慎出刀的大剑战斗。
- Godot 4.7.2 / GDScript / Compatibility；Blender 在战斗闭环后制作低模，通过 `.glb` 接入。
- Windows 桌面 + Chrome/Firefox 桌面浏览器；Mac 用浏览器验收，不交付 macOS 桌面包。
- 边做边学，工作日每天 2～3 小时、周末集中投入；5 周开发 + 1 周缓冲，以验收为阶段边界。
- 首版一张场地、一把大剑、一只怪物，单场约 3～5 分钟。暂不做联机、成长、背包、锻造、部位破坏、手机和手柄。
- 预留统一输入接口：当前仅接入键鼠，后续手柄／触屏通过适配器提供相同的移动、瞄准和动作输入，详见 [输入接口](INPUT.md)。

## 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M1 / 第 1 周 | 环境、竞技场、移动、鼠标朝向、镜头、Web 与 Windows 导出 | 能走、斜向不加速、不穿边界；浏览器输入和窗口缩放正常 |
| M2 / 第 2 周 | 训练靶、单段普攻、两档蓄力斩、翻滚、体力、状态机与命中反馈 | 单次攻击不重复扣血；动作互斥；体力不足不能启动消耗动作 |
| M3 / 第 3 周 | 怪物追击、横扫、扑击、冲撞、双方生命值、胜负和重开 | 招式可识别、可躲避、有反击窗口；能赢能输，连续完成 5 场 |
| M4 / 第 4 周 | Blender 大剑、女性铠甲猎人和双角荒原兽低模、骨骼基础动作、战斗 UI、原创音效 | 模型与判定一致；轮廓与三种招式清楚；动画、音效和重开无残留 |
| M5 / 第 5 周 | 场景美术、手感、数值、开始页、音量、性能、回归、打包和文档 | 两种浏览器和 Windows 实机验收；连续试玩 30 分钟 |
| 第 6 周 | 修复遗留问题及必要返工 | 不新增玩法系统 |

## 后续战斗约定

- WASD 移动，鼠标朝向；左键单段普攻，长按自动重复同一动作；右键按住蓄力、松开释放，满蓄力自动释放；空格翻滚。
- 攻击分前摇、有效命中、收招，出刀后不能任意翻滚取消。蓄力中可慢速移动，可翻滚放弃蓄力。
- 普攻不消耗体力；蓄力期间逐渐扣除体力，满蓄力累计消耗 30，取消不返还已消耗部分；翻滚启动时扣体力，不足不能启动。
- 翻滚有短暂无敌时间；攻击对同一目标只结算一次；怪物身体接触不扣血。
- 怪物攻击方向在前摇结束前锁定，招式后留出收招窗口。
- 同帧双方致命伤按失败结算，结算只显示一次。
- 模型、战斗逻辑和 HUD 分离；伤害、范围、消耗、动作时长使用 Resource 配置。
- 每阶段维护可运行版本和验收结果；M3 战斗闭环先于正式美术替换。

## M1 执行顺序

2026-09-15 状态：M1 实现、物理回归、Web/Windows 导出已完成，用户已确认浏览器验收通过。Windows 实机验收仍待完成，详见 [M1 验收记录](M1_ACCEPTANCE.md)。

1. 准备本地引擎、匹配模板和开发命令。
2. 建立真实 3D 物理场地、角色与俯视镜头。
3. 实现朝向、移动练习、暂停、失焦保护和重置。
4. 运行物理回归测试，导出浏览器版并实际试玩。
5. 导出 Windows 产物，记录尚需 Windows 实机验证的项目。

首阶段不提前加入攻击或怪物。先亲自验证移动与朝向，再进入 M2。
