# M3 分步实施计划

## 目标与边界

M3 建立第一版完整战斗闭环：一只怪物能够追击并使用横扫、扑击、冲撞三种可识别招式；玩家与怪物都有生命值；战斗可以胜利、失败和重新开始。

继续遵守已经确认的战斗约定：

- 怪物身体接触本身不造成伤害，只有招式的有效帧结算伤害。
- 怪物攻击方向在前摇结束前锁定，进入有效帧后不能继续追踪玩家。
- 玩家翻滚的无敌帧可以真实规避怪物攻击。
- 每次怪物攻击对玩家最多结算一次伤害。
- 同一物理帧双方受到致命伤时按玩家失败结算，胜负只结算一次。
- M3 继续使用程序化占位模型和动画；正式低模、骨骼动画与音效属于 M4。
- 开放式单场地优先使用直接转向与物理移动，不在 M3 引入导航网格、寻路或复杂行为树。

## 开发规则

每个步骤都是一个独立交付单元。一次开发只完成一个步骤，并满足以下条件后停止：

1. 本步骤的自动测试通过，已有输入、移动和 M2 战斗回归仍通过。
2. 本步骤涉及的状态和验收项已写入文档。
3. Web release 能正常导出；需要观察手感的步骤由用户刷新局域网版本验收。
4. 验收后创建一个独立 Git 提交，再开始下一步骤。
5. 不提前实现下一步骤；若当前步骤变大，继续拆分而不是跨步骤赶工。

## 实施步骤

### M3.1 玩家生命与受击基础

状态（2026-09-16）：实现、自动回归和浏览器 HUD 人工验收已完成。

范围：

- 为玩家增加最大生命、当前生命、受击接口、生命变化和倒地信号。
- 让受击逻辑尊重现有翻滚无敌状态，并防止同一次敌方攻击重复扣血。
- HUD 增加玩家生命显示和受击反馈。
- 重置时恢复玩家生命；本步骤暂不加入怪物。

完成标准：普通受击正确扣血，同一攻击只扣一次，无敌帧完全免伤，重置恢复生命；M2 行为不变。

### M3.2 怪物实体、生命与追击

状态（2026-09-16）：实现、自动回归和浏览器人工验收已完成。

范围：

- 新增程序化占位怪物及独立场景／脚本，接入玩家现有剑身命中检测。
- 怪物具有生命、受击、死亡状态，不再使用训练靶的“破坏后下一刀重建”规则。
- 实现待机、发现玩家、追击和攻击距离外停步；限制在竞技场边界内。
- 身体碰撞不造成伤害，死亡后停止移动和决策。

完成标准：怪物能稳定追到玩家附近，玩家能攻击并击杀怪物，接触不扣血，重置恢复初始位置和生命。

### M3.3 横扫与共用怪物攻击状态机

状态（2026-09-16）：实现、自动回归和浏览器人工验收已完成。

范围：

- 建立怪物攻击的 Resource 数据和 `windup → active → recovery` 共用状态流程。
- 实现第一次招式“横扫”：明显前摇、扇形／横向有效范围、一次命中、明确收招窗口。
- 前摇结束时锁定方向；有效帧中玩家离开范围或处于翻滚无敌时不受伤。
- 加入占位颜色／姿态提示，让前摇、有效帧和收招能被肉眼区分。

完成标准：横扫可识别、可走位或翻滚躲避、命中不重复、收招期间玩家可以安全反击。

### M3.4 扑击

状态（2026-09-16）：实现、自动回归和浏览器人工验收已完成。

范围：

- 在共用状态机上增加中距离扑击选择条件和数据配置。
- 前摇瞄准玩家，锁定后沿固定方向快速扑出，不在途中转弯追踪。
- 扑击使用沿运动路径的命中检测，并有落地后的明显收招窗口。

完成标准：扑击不会无限追踪，侧移或翻滚能够躲避，路径命中只结算一次，招式结束后回到追击。

### M3.5 冲撞

范围：

- 增加较远距离使用的冲撞，包括蓄势提示、固定方向高速移动和停止阶段。
- 处理竞技场边界：撞到边界应安全停止并进入收招，不能穿墙或卡出场地。
- 与横扫、扑击形成距离驱动的基础招式选择，并加入最小冷却，避免连续无缝出招。

完成标准：冲撞方向清晰、可躲避、不穿边界；三种招式都能在合理条件下出现，并留有反击时间。

### M3.6 战斗节奏与怪物决策

范围：

- 整理追击、转向、距离判断、招式权重和连续出招限制。
- 调整怪物生命、玩家生命、伤害、前摇、有效帧、收招和移动速度，使单场具备观察—躲避—反击循环。
- 保证同一随机种子或测试注入下行为可复现，避免自动测试依赖随机运气。

完成标准：三种招式轮廓与应对方式不同，怪物不会贴身连续锁死玩家，也不会长时间无动作。

### M3.7 胜负、重开与 HUD

范围：

- 加入进行中、胜利、失败三种对局状态；结算后冻结双方战斗行为。
- 怪物死亡判胜，玩家生命归零判负；同帧双方致命伤固定判负。
- HUD 显示双方生命、胜负结果和重开提示；R 可完整开始新一局。
- 确保暂停、失焦、重开不会留下移动、攻击或蓄力输入。

完成标准：可以稳定赢、稳定输并连续重开；结算信号和界面只出现一次，同帧致命规则有自动测试。

### M3.8 全量回归、构建与人工验收

范围：

- 补齐 M3 集成测试，运行输入、移动、M2 战斗和 M3 对局全量回归。
- 连续自动重置／重开，检查节点数量、生命、状态、攻击标记和输入均无残留。
- 导出 Web 与 Windows release，更新 README、开发计划和 `M3_ACCEPTANCE.md`。
- 通过浏览器连续完成至少 5 场，覆盖三种招式、胜负、翻滚规避和重开。

完成标准：所有自动测试通过，Web 构建可试玩，用户确认连续 5 场无阻断问题后标记 M3 完成。

## 推荐执行方式

后续每轮直接使用“开始 M3.1”“开始 M3.2”等指令。完成当前编号后先验收和提交，再进入下一编号。若某一步出现新的大范围需求，将其拆成 `.a`、`.b` 两个提交，不改变后续步骤编号。
